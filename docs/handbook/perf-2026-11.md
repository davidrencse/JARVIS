## Dedup review

Made: `jarvis/registry.py:109` validates membership in imported
`sysintents.STATUS_WHAT`; `jarvis/actions.py:310` generates the schema enum with
`list(STATUS_WHAT)`. Tuple ordering and list-shaped JSON schema preserved. Imports
are acyclic (`sysintents` depends on platforms, not registry/actions).
Original files saved as `jarvis/registry.py.pre-dedup` and
`jarvis/actions.py.pre-dedup`; handbook index also saved as `.pre-dedup`.

Left alone:
- UI TTL versus Prober's 55 s cache: Prober serializes probe execution under a lock,
  supports explicit refresh and uses result checked_at. `_Ttl` computes outside its
  lock and permits duplicate concurrent misses; substitution would alter behavior.
- Credits caches invalidate by credential signature and reset deadlines, preserve
  provider error readings and manual overrides; generic TTL cannot replace them cheaply.
- Module/tree caches share stamp lookup shape but cache different values and AST
  dependency data. Their file-change invalidation differs from TTL. A generic cache
  abstraction would exceed this small review.
- Browser visibility guards are repeated conditions, not duplicate helpers.
  `window.Jarvis` exports no visibility/idle helper; knowledge is a separate page,
  ear polls an API and terrain schedules WebGL with reduced-motion/mic state.
- Test overlap retained: voice retry tests prove eventual success versus no retry
  storm; UI traversal is checked both directly and over HTTP; parser/eval phrases
  overlap deliberately for focused assertions and scorecard coverage. The room-space
  near miss appears in both parser and disk tests with different device configs.
  AST comparison found no identical test bodies across the five reviewed Python test
  modules, and no repeated text among eval cases. Clock fakes differ
  in API (`now` versus `t`), and extracting test scaffolding buys little.
- The two ONNX arena assignments configure different model sessions; a helper for
  one property would obscure model-specific thread/session setup.
